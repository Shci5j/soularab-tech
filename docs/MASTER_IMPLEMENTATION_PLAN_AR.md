# الخطة التنفيذية الموحدة — SOULARAB TECH

> هذه الوثيقة هي مرجع التنفيذ الوحيد للأقسام وسير العمل. لا تعني أن كل المحركات مكتملة؛ حالة كل قدرة موضحة أدناه، ولا تتحول أي قدرة إلى منفذة إلا بعد كود واختبار موثقين.

## 1) الهدف ومبادئ التشغيل

بناء مساحة عمل شخصية محلية أولاً، تعمل من واجهة موحدة وتديرها روح (ROOH AI). تبقى بيانات المشاريع محلية افتراضياً، ولا يُفعّل اتصال خارجي أو خدمة مدفوعة أو نشر أو تعديل مؤثر إلا بتفويض صريح من المالك.

قواعد ثابتة:
- روح تفهم الطلب وتقترح خطة وتحدد القسم والأدوات، لكنها لا تنفذ ولا تصدر أوامر تشغيل دون موافقة صريحة لكل إجراء مؤثر.
- الموافقة تسجل القرار ولا تعني التنفيذ تلقائياً؛ التنفيذ خطوة منفصلة، قابلة للإلغاء، ومقيدة بالنطاق.
- لا وصول لروح إلى الخزنة؛ الاستثناء الوحيد مساحة «ملاحظات روح» بإذن صريح، ولا تستطيع قراءة بقية الخزنة.
- فصل بيانات كل مشروع وملفاته، وسجل تدقيق للعمليات، ونسخ احتياطي واستعادة مختبران.
- لا تُحمّل جميع النماذج دفعة واحدة. اختيار المحرك بحسب المهمة والموارد، ثم تفريغه عند الانتهاء.
- فحص ترخيص كل برنامج ونموذج وأوزان وبيانات على حدة؛ مجانية الكود لا تعني مجانية موارد التشغيل.
- دعم الهاتف بواجهة خفيفة؛ مهام التوليد الثقيلة تنفذ على عقدة يملكها المستخدم أو جهاز متاح بعد الموافقة، لا على افتراض أن الهاتف قادر عليها.

## 2) واجهة العمل الموحدة

واجهة واحدة باسم «واجهة العمل» تحتوي:
1. مربع وصف المهمة باللغة الطبيعية.
2. محدد القسم (تلقائي بواسطة روح أو يدوي من المستخدم).
3. مرفقات اختيارية: صورة مرجعية، فيديو، صوت، مستند أو ملفات مشروع.
4. معاينة خطة روح: الهدف، الخطوات، المحركات، الملفات المتأثرة، المخاطر، والوقت/الموارد التقديرية إن توفرت.
5. موافقات واضحة منفصلة بحسب الإجراء.
6. تقدم حيّ، سجل أحداث، إيقاف/إلغاء، ومخرجات قابلة للمراجعة والحفظ في المشروع.
7. سجل المهام والمشاريع السابقة وإعادة تشغيل آمنة بعد مراجعة المستخدم.

تدفق المهمة الموحد:
استقبال الطلب ← فهمه وتصنيفه ← تحديد القسم/الأقسام ← تحليل المتطلبات ← خطة قابلة للتحرير ← فحص القدرات والموارد ← عرض الموافقات ← تنفيذ مفوض فقط ← تحقق واختبارات ← عرض النتيجة ← حفظ اختياري في المشروع ← سجل تدقيق.

حالات المهمة الموحدة:
draft, planning, waiting_approval, queued, running, verifying, completed, failed, cancelled.
كل انتقال مسجل مع السبب والوقت؛ لا يتحول queued إلى running تلقائياً دون تفويض تنفيذ.

## 3) روح — ROOH AI

روح هي المنسق المركزي وليست مجرد نافذة دردشة:
- المستوى المنخفض: فهم بسيط، تصنيف، أسئلة توضيحية ضرورية، توجيه.
- المتوسط: تحليل المتطلبات، تقسيم المهمة، إعداد خطة واستدعاء أدوات مقيدة.
- المرتفع: تنسيق مشاريع متعددة الأقسام، مراجعة الجودة، تحليل المخاطر والتبعيات.
- اختيار المستوى تلقائياً حسب تعقيد المهمة والموارد، مع تحكم يدوي.
- نموذج أساسي واحد قابل للتبديل مع أدوات/سياقات متخصصة أفضل من تشغيل عدة نماذج ضخمة دائماً.
- ذاكرة سياقية للمشروع بإذن المستخدم، مع فصل صارم عن الخزنة.
- لا أوامر shell أو شبكة أو ملفات عامة أو تعديل مستودع أو نشر دون موافقة صريحة ومحددة.

## 4) الأقسام الاثنا عشر ومخرجاتها

### 1. إنشاء المواقع الإلكترونية
- موجز الموقع، هيكل الصفحات والتنقل، التصميم المتجاوب، محتوى الصفحات.
- منشئ صفحات ومكونات قابلة لإعادة الاستخدام، معاينة محلية، فحص إمكانية الوصول والأداء.
- حفظ المصدر والأصول ضمن مساحة المشروع، واختبارات بناء.
- النشر وربط النطاق خطوة مستقلة تتطلب موافقة ونطاقاً ووجهة محددين.
- الحالة الحالية: يوجد منشئ صفحات ثابتة ومعاينة وتنزيل/حفظ مخرجات؛ لا يعد ذلك منصة نشر مكتملة.

### 2. المتاجر الإلكترونية
- كتالوج المنتجات، التصنيفات، البحث، السلة، الطلبات، إدارة المخزون ولوحة إدارة.
- بوابات الدفع والشحن والضرائب لا تُفعّل إلا بعد تحديد البلد والمزود ومراجعة الشروط وموافقة المالك.
- وضع تجريبي لا يجمع أموالاً قبل اعتماد الإعدادات.
- الحالة الحالية: تحتاج محرك متجر مستقل واختبارات دورة الطلب؛ لا تُعامل كمنشئ مواقع عادي.

### 3. تصميم الشعارات
- موجز العلامة، بحث مرجعي، مفاهيم أولية، متغيرات، ملفات SVG قابلة للتحرير وتصدير صيغ مناسبة.
- الحفاظ على أصول وهوية SOULARAB TECH الرسمية وعدم تعديلها تلقائياً.
- فحص حقوق الخطوط والرموز والأصول، وتسليم ملفات المصدر.
- الحالة الحالية: استوديو مسودات هوية وتصدير SVG/TXT؛ ليس محرك تصميم احترافي مكتمل.

### 4. توليد الصور
- فهم الوصف والمراجع، إعداد prompt منظم، اختيار نموذج/سير عمل محلي، معاينة النتائج وتوثيق النموذج والترخيص.
- دعم التوليد والتحرير والمعالجة على محرك متوافق مثل ComfyUI عند تشغيله محلياً.
- إدارة ذاكرة GPU والصف والمهل وإلغاء المهمة.
- الحالة الحالية: نقطة تكامل اختيارية مع ComfyUI؛ ليست خدمة توليد مستقلة ولا تعمل ما لم يكن المحرك متاحاً.

### 5. إنشاء الفيديو
- تخطيط المشاهد واللقطات والمدة والنص والصوت والترجمة.
- خط إنتاج قابل للتبديل: صور/إطارات، تحريك، تركيب، صوت، ترجمة، إخراج وفحص.
- حدود واضحة للوقت والذاكرة والتخزين؛ لا وعد بتوليد فيديو ثقيل على الهاتف.
- الحالة الحالية: تخطيط وتكاملات غير مكتملة؛ يلزم بناء pipeline واختبارات ملفات ومزامنة.

### 6. إنشاء التطبيقات
- متطلبات المنتج، تدفقات المستخدم، تصميم الواجهات، بنية الكود، إنشاء المصدر والاختبارات.
- بناء الويب أولاً، ثم Android package عند استقرار المنتج؛ فحص التوقيع والأذونات والحجم والتثبيت.
- حفظ المصدر وسجل الإصدارات وإتاحة معاينة آمنة.
- الحالة الحالية: منشئ تطبيقات/واجهات ثابتة أولي؛ لا يوجد APK نهائي بعد.

### 7. التصميم الجرافيكي
- لوحات ألوان، تخطيطات، منشورات، بطاقات، مطبوعات وقوالب قابلة لإعادة الاستخدام.
- ملفات قابلة للتحرير وتصدير PDF/PNG/SVG مع دقة وأبعاد محددة.
- التحقق من حقوق الأصول والخطوط وملاءمة الطباعة.
- الحالة الحالية: تأسيس/مسودات؛ يلزم محرر تصميم وقوالب ومحرك تصدير موحد.

### 8. المستندات والملفات
- قراءة وإنشاء وتحرير DOCX/PDF/XLSX/PPTX/CSV/TXT/MD عند الحاجة.
- استيراد آمن، فحص نوع الملف والحجم، معاينة، تصدير، وإدارة نسخ.
- عزل ملفات كل مشروع، عدم تصفح الجهاز خارج المسارات المصرح بها.
- الحالة الحالية: إدارة ملفات المشاريع والرفع والتنزيل موجودة؛ أدوات المستندات تحتاج توسيع واختبارات تنسيقات.

### 9. الوكلاء الذكيون
- قوالب وكلاء بمهام محددة وأدوات allowlist وصلاحيات أقل ما يمكن.
- خطط متعددة الخطوات قابلة للتحرير والمراجعة؛ كل أثر خارجي أو تعديل ملف/كود يحتاج موافقة.
- حدود زمنية وميزانية موارد وسجل أحداث، إيقاف فوري، ومنع حلقات التنفيذ غير المنتهية.
- الحالة الحالية: مساعد تخطيط وخطط مهام وموافقات وسجل؛ التنفيذ الفعلي محدود وليس وكيلاً مستقلاً مفتوح الصلاحيات.

### 10. الأتمتة والمهام
- جدولة محلية ومشغلات يحددها المستخدم، طابور، إعادة محاولة محدودة، وسياسة فشل.
- تكاملات المتصفح/الملفات/النظام في بيئة معزولة وبقائمة سماح.
- طلب موافقة قبل إرسال أو شراء أو نشر أو حذف أو تعديل خارجي.
- الحالة الحالية: طابور مهام وموافقات أولية؛ لا يوجد منفذ أتمتة عام مكتمل.

### 11. SOULARAB HUB
- مستودعات خاصة يملكها المستخدم، Git داخلي، commits/branches/merges، مراجعات، issues، CI، releases.
- استيراد/تصدير مستودع بإذن، صلاحيات دقيقة، سجل تغييرات، نسخ احتياطي واستعادة.
- فصل مشاريع العملاء وتشفير الأسرار وعدم إرسال الكود إلى خدمة خارجية افتراضياً.
- الحالة الحالية: استعراض GitHub عام للقراءة في بعض الفروع؛ لا يوجد مستودع Git خاص داخلي مكتمل.

### 12. الجذر — AL JATHR
- اكتشاف أجهزة ضمن شبكة/نطاق يحدده المالك، مع تعريف واضح للأجهزة المدعومة.
- فحص سلبي أو تشخيص منخفض الأثر، ومصادقة رسمية وبروتوكولات موثقة مثل ONVIF/RTSP عند دعمها.
- قراءة معلومات الحالة المسموح بها، ثم مسارات صيانة واستعادة رسمية لكل طراز.
- لا تجاوز حماية، ولا سرقة كلمات مرور، ولا وصول إلى أجهزة الغير، ولا إخفاء نشاط غير مصرح. توقيع أو إذن عام لا يبرر تجاوز المصادقة.
- الحالة الحالية: واجهة تشخيص معلومات المتصفح فقط؛ لا يوجد ماسح أجهزة أو محرك صيانة شبكات.

## 5) SOULARAB VAULT — الخزنة المستقلة

- قسم مستقل خارج الأقسام الاثني عشر.
- مصادقة فعلية PIN قوي/بيومتري عبر واجهات النظام حيث تتوفر، ومفاتيح تشفير لا تُخزن بجانب البيانات.
- تشفير المحتوى محلياً، قفل تلقائي، حماية من التخمين، نسخ احتياطي مشفر، واستعادة بمفتاح يملكه المستخدم.
- صلاحيات روح صفر على محتويات الخزنة؛ لا ترى ولا تبحث ولا تقرأ أي عنصر.
- مساحة ملاحظات روح منفصلة: لا كتابة إلا بعد موافقة المستخدم على المحتوى المحدد؛ لا قراءة لاحقة لروح، والمستخدم هو من ينقل المحتوى للخزنة.
- الحالة الحالية: ملاحظات محلية/خلفية أولية؛ لا تُعد خزنة آمنة قبل تنفيذ التشفير والمصادقة واختبارات الاستعادة.

## 6) البنية التقنية المشتركة

- واجهة: React/Vite حالياً، PWA، RTL/LTR، ترجمة مركزية، ثيم فاتح/داكن، تصميم متجاوب.
- API: FastAPI مع مخططات تحقق واضحة وإصدارات API.
- البيانات: SQLite للمستخدم الواحد؛ ترحيل منظم وقابل للاختبار.
- تنفيذ المهام: مدير مهام مركزي، queue، workers معزولة، سجلات أحداث، cancellation وtimeouts.
- المحركات: واجهات adapters موحدة؛ llama.cpp للمحادثة، ComfyUI للصور، whisper.cpp للصوت، وأدوات بناء/تصدير للمواقع والتطبيقات والملفات.
- التخزين: مساحة مشروع مع manifest للأصول والنسخ؛ لا مسارات حرة خارج sandbox.
- Android: حاوية تطبيق خفيفة مع WebView/PWA أو Capacitor بعد حسم الصلاحيات والتخزين والاتصال المحلي؛ لا تحزم النماذج الثقيلة داخل APK.
- الشبكة: loopback افتراضياً؛ أي عقدة بعيدة تحتاج إعداداً وموافقة وتوثيق اتصال آمن.

## 7) الأمن والحوكمة

- threat model لكل وحدة، مصادقة وتفويض على الخادم وليس الواجهة فقط.
- رموز وصول قابلة للإبطال وتخزين آمن، حماية CSRF عند استخدام cookies، وتحديد المعدل.
- التحقق من الملفات والامتدادات والمحتوى، منع path traversal، وعزل عمليات المعالجة.
- سجل تدقيق لا يحتوي أسراراً أو محتوى حساساً بلا ضرورة.
- اختبارات موافقة/رفض/إلغاء/إعادة تشغيل، واختبارات صلاحيات الخزنة.
- مراجعة تراخيص وSBOM وتحديثات تبعيات وفحص أسرار قبل كل إصدار.
- لا نشر أو DNS أو مدفوعات أو إرسال بيانات أو ربط حسابات إلا بتفويض مستقل.

## 8) مراحل التنفيذ الموحدة (بوابات قبول)

### المرحلة A — تثبيت الأساس
- توحيد فرع عمل مرجعي، توثيق الحالة الحقيقية، إصلاح CI، ترحيلات DB، API schemas، الاختبارات الأساسية.
- قبول: build + backend tests + lint/security checks ناجحة، ولا regressions.

### المرحلة B — واجهة العمل وروح
- واجهة أمر موحدة، اختيار قسم، مرفقات، خطة قابلة للتحرير، حالة المهمة، سجل، ومستويات روح.
- قبول: اختبار end-to-end من الطلب إلى خطة وموافقة ثم نتيجة تجريبية دون تنفيذ غير مفوض.

### المرحلة C — مدير المهام والصلاحيات
- حالات موحدة، event log، approval binding، cancellation، queue/worker interface، حدود الموارد.
- قبول: لا يمكن الانتقال إلى تنفيذ فعلي دون تفويض صالح؛ اختبارات صلاحيات وتزامن.

### المرحلة D — محركات الأقسام حسب الأولوية
1. الملفات والمستندات + إدارة المشاريع.
2. المواقع والتطبيقات.
3. التصميم والشعارات والجرافيك.
4. المحادثة والوكلاء والأتمتة.
5. الصور والصوت ثم الفيديو وفق توفر الموارد.
6. HUB الداخلي.
7. الجذر ضمن نطاق الأجهزة المصرح بها.
- لكل محرك: adapter، فحص توفر، متطلبات موارد، مدخلات/مخرجات، إلغاء، اختبارات، توثيق الترخيص.

### المرحلة E — الخزنة
- تصميم تشفير ومفاتيح ومصادقة واستعادة، ثم واجهة آمنة.
- قبول: اختبارات تسرب وصلاحيات واستعادة، وعدم وصول روح لأي محتوى.

### المرحلة F — الاستقرار والتشغيل الذاتي
- تشغيل محلي، إعدادات النسخ الاحتياطي، مراقبة الموارد، logs، تحديثات وتراجع.
- قبول: تثبيت نظيف، تشغيل دون حساب خارجي، استعادة نسخة احتياطية ناجحة.

### المرحلة G — Android APK
- اختيار حاوية Android، إعداد الأذونات، تخزين آمن، اتصال بالخادم المحلي، معالجة انقطاع الشبكة.
- قبول: APK debug ثم release موقّع، تثبيت واختبار على جهاز فعلي، توثيق القيود.

## 9) تعريف الإنجاز

لا توصف أي وحدة بأنها «مكتملة» إلا إذا:
- لها واجهة قابلة للاستخدام ومحرك فعلي متصل.
- تعمل على مسار محلي موثق أو تكامل اختياري معلن بوضوح.
- لها اختبارات نجاح وفشل وحدود صلاحيات وإلغاء.
- مخرجاتها محفوظة/مصدرة ويمكن إعادة فتحها.
- وثائق التشغيل والتبعيات والتراخيص محدثة.

## 10) سجل الحالة عند إنشاء هذه الخطة

- موجود: أساس React/Vite وFastAPI وSQLite وPWA، إدارة مشاريع وملفات، محرك llama.cpp محلي، بعض منشئات المخرجات الثابتة، مسارات تخطيط وموافقات، تشخيص محركات محلية، وواجهات أولية للأقسام.
- جزئي: واجهة موحدة، روح كمنسق، منشئات المواقع/التطبيقات، استوديو التصميم، الوكلاء، الوسائط المحلية.
- غير مكتمل جوهرياً: متجر متكامل، فيديو pipeline، محرر جرافيك متكامل، مستندات شاملة، أتمتة عامة، HUB Git داخلي، الجذر للأجهزة، خزنة مشفرة، APK نهائي.
- هذه الحالة لقطة من فحص الفروع والوثائق المتاحة وقت إعداد الخطة، وليست شهادة تشغيل على جهاز المستخدم أو نشر إنتاجي.

## 11) سياسة التقدم

تُنفذ الأعمال على فروع مستقلة، وتُربط كل دفعة ببوابة قبول واختبارات. لا دمج إلى main ولا نشر ولا تفعيل خدمة خارجية أو مدفوعة ضمن هذه الخطة دون موافقة صريحة منفصلة من المالك.
