# المرحلة الأولى: تثبيت النواة المحلية

## النطاق
هذه المرحلة تثبّت دورة المهمة المحلية من واجهة التطبيق إلى SQLite والموافقة والطابور والعامل والنتيجة، دون دمج أو نشر أو تشغيل خدمات خارجية.

## عقد المهمة
- تنشأ المهمة بالحالة `waiting_approval` مع سجل موافقة مرتبط بها داخل معاملة SQLite واحدة.
- لا يلتقط العامل المهمة إلا إذا كانت `queued`، ولديها موافقة `approved`، ولم يُطلب إلغاؤها، وما زال لها عدد محاولات.
- يتم اختيار المهمة وادعاء ملكيتها وتسجيل `task_started` ضمن معاملة كتابة واحدة.
- الحد الافتراضي ثلاث محاولات لكل مهمة. لا توجد إعادة محاولة تلقائية بعد الفشل؛ يمكن للمستخدم طلب `retry` يدوياً إذا بقيت الموافقة صالحة ولم ينته الحد.
- كل انتقال حالة مشروط بالحالة السابقة لتجنب سباقات التحديث بين العامل والواجهة.
- تُحفظ أوقات البدء والانتهاء وعدد المحاولات وطلب الإلغاء في سجل المهمة.

## الإلغاء
- المهمة المنتظرة أو المتوقفة مؤقتاً تنتقل مباشرة إلى `cancelled`.
- إذا ألغى المستخدم مهمة ما زالت بانتظار الموافقة، يُغلق طلب الموافقة المعلق كـ `rejected` مع ملاحظة `cancelled_by_user` داخل المعاملة نفسها.
- المهمة الجارية تسجل `cancel_requested=1`. الإلغاء تعاوني: لا يقتل طلب HTTP أو الاستدلال الجاري قسرياً، بل يطبق العامل الحالة `cancelled` عند نقطة الإنهاء الآمنة.
- إذا أُغلق التطبيق بعد طلب الإلغاء، يحول مسار الاسترداد المهمة الجارية إلى `cancelled`.

## الاسترداد بعد توقف التطبيق
- A وB وD فقط يعاد إدراجها تلقائياً إذا كانت الموافقة معتمدة، ولم يطلب المستخدم إلغاءها، وما زالت هناك محاولات.
- C وE لا يعاد تشغيلهما تلقائياً لتجنب تكرار توليد الوسائط أو الكتابة؛ تحفظان كـ `failed` للمراجعة اليدوية.
- المهام غير المعتمدة أو المستنفدة للمحاولات تتحول إلى `failed`.
- جميع قرارات الاسترداد وسجلها تُكتب ضمن معاملة واحدة.

## قاعدة البيانات
ترتفع نسخة المخطط من 4 إلى 5 بإضافة:
- `attempt_count`
- `max_attempts`
- `cancel_requested`
- `started_at`
- `finished_at`

تتم الإضافة عبر `onUpgrade` دون حذف الجداول أو إعادة إنشاء قاعدة البيانات، مع فهرس مخصص لقراءة الطابور.

## حدود الأمان
- لا يسمح بتوجيه قسم غير معروف إلى A افتراضياً؛ تُرفض الأقسام غير المدعومة برسالة تحقق.
- تُرفض أجسام الطلبات التي تعلن Content-Length أكبر من 36 MiB قبل تحليلها، ويعاد فحص الحجم بعد التحليل.
- لا ينفذ هذا التغيير أوامر Shell ولا يفتح اتصالات خارج loopback.

## اختبارات المرحلة
اختبارات `LocalTaskStateTest` تغطي أهلية إعادة المحاولة، أولوية الإلغاء، وسياسة الاسترداد للعقد A-E. كما يجب أن ينجح:
- `npm test`
- `npm run build`
- `./gradlew testDebugUnitTest`
- `./gradlew assembleDebug`

نجاح CI لا يثبت التشغيل على هاتف فعلي. يلزم اختبار Android يدوي لدورة الموافقة والتنفيذ والإلغاء وإعادة التشغيل قبل إعلان اعتماد المرحلة.
