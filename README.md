# SOULARAB TECH

منصة محلية أولاً لبناء مساحة عمل موحدة للذكاء الاصطناعي والتصميم والمواقع والتطبيقات.

> الحالة: **0.7.0 — Unified Workspace / مساحة العمل الموحدة**. تضم الواجهة مساعد Ollama محلياً، وإدارة المشاريع والملفات، ومستكشف GitHub للقراءة، وتشخيص المتصفح، والخزنة المحلية، وتفضيلات الواجهة واللغة.

## وظائف الواجهة الحالية

- الرئيسية: مساعد روح، الأقسام الأربعة، وتاريخ يومي تلقائي.
- منشئ المواقع والتطبيقات: إنشاء واجهات ثابتة مع معاينة داخلية وتنزيل HTML مستقل.
- استوديو التصميم: مسودة هوية قابلة للتصدير بصيغ SVG وTXT دون المساس بالشعار الرسمي.
- الوكلاء: إعداد خطط متعددة الخطوات وإرسالها إلى نظام الموافقات مع حفظ نسخة في الخزنة؛ لا يبدأ التنفيذ تلقائياً.
- النطاقات والاستضافة: التحقق من اسم النطاق وإنشاء قائمة تحقق للنشر، دون إجراء تغييرات DNS أو شراء النطاق.
- اللغة: تبديل العربية والإنجليزية مع اتجاه RTL/LTR؛ ترجمة الوحدات المتخصصة لا تزال تتوسع.
- الإعدادات: المظهر، عائلة الخط، حجم النص، كثافة الواجهة، وتقليل الحركة. التفضيلات محفوظة محلياً.
- سولاراب هوب: استعراض مستودعات GitHub العامة وملفات الجذر وبيانات المستودع للقراءة فقط. لا يوجد تعديل أو دفع إلى المستودعات من هذه الواجهة.
- الجذر: فحص معلومات المتصفح والشاشة والاتصال والخصائص التي يسمح المتصفح بعرضها. لا تدّعي الصفحة امتلاك صلاحيات نظام التشغيل أو root.
- الخزنة: حفظ الملاحظات والأفكار والمهام والمراجع محلياً مع تصدير JSON.
- الوسائط المحلية: تكامل API مع ComfyUI لتشغيل سير عمل الصور، وwhisper.cpp لتفريغ الملفات الصوتية عند تشغيل المحركين على جهاز الخادم.
- الأمان: طلبات موافقة وسجل تدقيق عند اتصال الخادم.
- الرجوع: التنقل داخل سجل التطبيق مع دعم زر الرجوع في المتصفح والهاتف.

## البنية

- **Frontend:** React 18 + Vite، واجهة عربية RTL ومتجاوبة للهواتف والحواسيب.
- **Backend:** Python + FastAPI.
- **Storage:** SQLite محلياً كبداية، مع قابلية إضافة PostgreSQL عند الانتقال إلى خادم متعدد المستخدمين.
- **PWA:** manifest وService Worker للتثبيت والتخزين المؤقت.
- **Safety:** سجل تدقيق، طابور موافقات، وعدم تنفيذ أي إجراء لمجرد تسجيل الموافقة.

## التشغيل

### المتطلبات
- Node.js 20 أو أحدث.
- Python 3.10 أو أحدث.

### الخلفية
```bash
cd backend
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

### الواجهة
من جذر المستودع:
```bash
npm install
npm run dev
```
افتح عنوان Vite الظاهر في الطرفية. الواجهة تتصل افتراضياً بـ `http://127.0.0.1:8000`. لتغيير ذلك أنشئ ملف `.env.local` في الجذر وضع `VITE_API_BASE_URL=http://127.0.0.1:8000`.

## الأمان والخصوصية

- لا توجد بيانات دخول تجريبية مضمنة في الواجهة.
- الخادم محلي افتراضياً ويقبل CORS من عناوين التطوير المحلية فقط.
- في وضع الإنتاج يجب ضبط `SOULARAB_API_TOKEN` بقيمة قوية وسرية، وتقييد CORS إلى النطاقات الموثوقة، ووضع الخادم خلف HTTPS.
- لا تُسجل أسرار أو رموز وصول في المستودع.
- الموافقة على طلب تسجل القرار فقط؛ **لا تنفذ** أمراً أو اتصالاً أو تعديلاً. يلزم مسار تنفيذ منفصل ومراجعة أخرى.
- لا يوجد اتصال تلقائي بخدمة سحابية. تكامل Ollama يتصل بعنوان loopback فقط (localhost/127.0.0.1) على جهاز الخادم، ولا يقبل عنواناً عاماً أو عنوان شبكة LAN.
- يتطلب المساعد تشغيل Ollama وتثبيت نموذج محلي. عيّن `OLLAMA_BASE_URL` فقط إذا كان عنوان الخدمة على loopback وبروتوكول HTTP.
- واجهة الهاتف لا تشغّل النموذج بنفسها؛ تستعمل الخادم المحلي كوسيط.

### تشغيل المساعد المحلي
1. ثبّت Ollama على الجهاز الذي سيشغّل الخادم: https://ollama.com/download
2. نزّل نموذجاً يناسب الذاكرة المتاحة، مثلاً `ollama pull qwen2.5:3b`، بعد مراجعة بطاقة النموذج وترخيصه وشروط الاستخدام.
3. شغّل الخادم والواجهة كما سبق، ثم افتح قسم «المساعد الذكي» واختر النموذج.
4. عنوان Ollama الافتراضي هو `http://127.0.0.1:11434`؛ الاتصال محصور محلياً ولا يدعم مزوداً بعيداً في هذه المرحلة.
5. عند فتح الواجهة من هاتف عبر الشبكة المحلية، أضف عنوان الواجهة إلى `SOULARAB_CORS_ORIGINS` في بيئة الخادم، مع إبقاء الوصول إلى API محمياً برمز قوي.

### محركات الوسائط المحلية

يمكن ربط محركات الوسائط دون استخدام خدمات سحابية:

- **ComfyUI:** اضبط `COMFYUI_BASE_URL` (الافتراضي `http://127.0.0.1:8188`). يعرض قسم الصور نماذج Checkpoint المثبتة تلقائياً، ويتيح إدخال وصف موجب وسلبي والأبعاد وخطوات التوليد لإنشاء سير عمل txt2img قياسي. يمكن أيضاً إرسال سير عمل API مخصص. تُعاد حالة المهمة ومعرّفها، ثم يمكن استعراض سجل النتائج وعرض صور المخرجات عبر وسيط آمن محدود بملفات الصور الناتجة. ضع النماذج في `models/checkpoints` داخل ComfyUI.
- **whisper.cpp:** اضبط `WHISPER_CPP_BASE_URL` (الافتراضي `http://127.0.0.1:8080`). شغّل خادم whisper.cpp مع واجهة `/health` و`/inference`، ثم ارفع ملفاً صوتياً مدعوماً من قسم الصور والصوت. الحد الأقصى 25 MB. يدعم WAV مباشرة؛ أما MP3 وM4A وOGG وWEBM وFLAC فتتطلب تشغيل whisper-server بخيار `--convert` وتثبيت FFmpeg.
- العناوين مقيدة بـ localhost أو loopback. في Docker فقط، يمكن تفعيل `SOULARAB_ALLOW_DOCKER_MEDIA=true` للسماح بأسماء خدمات `comfyui` و`whisper` داخل شبكة Docker الخاصة، مع ضبط العنوانين إلى أسماء الخدمات الصحيحة. لا تفتح منافذ هذه المحركات للإنترنت.
- وجود واجهة التكامل لا يعني أن المحرك مثبت؛ ستظهر الحالة غير متصلة حتى ينجح فحص الخدمة الفعلية.

### إدارة المشاريع
- من قسم «الملفات والمشاريع» أنشئ مساحة مشروع بعنوان ووصف.
- يحتفظ الخادم ببيانات المشاريع في SQLite وينشئ مجلداً منفصلاً داخل `backend/data/workspaces/<project-id>`.
- يمكن أرشفة المشروع دون حذف مجلده أو ملفاته.
- يمكن عرض ملفات المشروع ورفعها وتنزيلها من الواجهة. الحد الأقصى 10 MB للملف، وتُرفض المسارات والملفات التنفيذية الشائعة. لا توجد صلاحية لتصفح ملفات الجهاز خارج مجلد المشروع.

### النشر الذاتي باستخدام Docker
1. ثبّت Docker Engine وDocker Compose على جهاز الخادم.
2. انسخ ملف الإعدادات النموذجي: `cp .env.docker.example .env`.
3. غيّر `SOULARAB_API_TOKEN` إلى قيمة عشوائية قوية وسرية قبل التشغيل.
4. شغّل المنصة: `docker compose up -d --build`.
5. افتح `http://SERVER-IP:8080` من الهاتف أو الحاسوب على الشبكة المسموح بها.
6. لتشغيل Ollama داخل Docker أيضاً: `docker compose --profile ai up -d --build`، ثم نزّل نموذجاً يدوياً: `docker compose exec ollama ollama pull qwen2.5:3b` بعد مراجعة ترخيصه واحتياجات الذاكرة.
7. البيانات تحفظ في Docker volumes ولا تُحفظ داخل صورة الحاوية.

**تنبيه أمني:** المنفذ 8080 يقدم HTTP. عند إتاحته عبر الإنترنت، ضعه خلف reverse proxy يدعم HTTPS، واستخدم نطاقاً موثوقاً، ولا تكشف منفذ FastAPI الداخلي 8000 أو خدمة Ollama للإنترنت. لا توجد عملية نشر تلقائي إلى الإنترنت.

## الوحدات المخطط لها

1. المساعد والنماذج المحلية: Ollama أو llama.cpp بعد اختيار نموذج وترخيصه.
2. التصميم والوسائط: ComfyUI كخيار تكامل محلي، مع التحقق من متطلبات GPU.
3. الصوت: whisper.cpp.
4. أتمتة المتصفح: Playwright ضمن بيئة معزولة وموافقات لكل عملية مؤثرة.
5. المواقع والنشر والنطاقات: موصلات قابلة للتبديل، لا مفاتيح SaaS إجبارية.
6. إدارة المشاريع والملفات والنسخ الاحتياطية.
