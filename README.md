# SOULARAB TECH

منصة محلية أولاً لبناء مساحة عمل موحدة للذكاء الاصطناعي والتصميم والمواقع والتطبيقات.

> الحالة: **0.16.3 — API Transport Security & Localization / أمان اتصال الخادم والترجمة**. تضم الواجهة محرك روح المحلي المبني على llama.cpp، وإدارة المشاريع والملفات، ومستكشف GitHub للقراءة، وتشخيص المتصفح، والخزنة المحلية، وإعدادات الواجهة والمنطقة وإمكانية الوصول، والنسخ الاحتياطي للتفضيلات، وقفل جلسة الوصول الاختياري عند عدم النشاط، ومؤشر وضع الأمان الفعلي، وتصدير فهرس ملفات المشاريع، وتقييد سير عمل ComfyUI بقائمة عقد مسموحة، وتحميل إجراءات التنفيذ الآمنة من سجل الخادم مباشرة مع أوصاف عربية وإنجليزية، ودرجة حرارة افتراضية قابلة للضبط لمحادثات روح، ورابط تجاوز التنقل لمستخدمي لوحة المفاتيح، والتحقق من عنوان الخادم قبل إرسال رمز الوصول بحيث يُسمح بـHTTPS أو loopback محلي فقط، مع ترجمة أخطاء الخادم في الواجهة الإنجليزية.

## وظائف الواجهة الحالية

- الرئيسية: مساعد روح، الأقسام الأربعة، وتاريخ يومي تلقائي.
- منشئ المواقع والتطبيقات: إنشاء واجهات ثابتة مع معاينة داخلية وتنزيل HTML مستقل، مع اقتراح محتوى الصفحات وهيكل الأقسام بواسطة نموذج روح المحلي عبر llama.cpp بعد مراجعة المستخدم.
- استوديو التصميم: مسودة هوية قابلة للتصدير بصيغ SVG وTXT، مع موجز استراتيجية العلامة بمساعدة نموذج روح المحلي، دون المساس بالشعار الرسمي أو تغيير ألوانه تلقائياً.
- الوكلاء: اقتراح خطوات الخطة بمساعدة نموذج روح المحلي، ثم مراجعتها وتعديلها قبل إنشاء مهمة مرتبطة بطلب موافقة في معاملة SQLite واحدة. تعرض الواجهة المهام وسجل حالاتها وطلبات الموافقة السابقة؛ لا يبدأ التنفيذ تلقائياً.
- النطاقات والاستضافة: التحقق من اسم النطاق وإنشاء قائمة تحقق للنشر، دون إجراء تغييرات DNS أو شراء النطاق.
- اللغة: تبديل العربية والإنجليزية مع اتجاه RTL/LTR؛ ترجمة الوحدات المتخصصة لا تزال تتوسع.
- الإعدادات: العربية والإنجليزية، تنسيق التاريخ والمنطقة الزمنية، المظهر، الخط وحجمه، كثافة الواجهة، تقليل الحركة والتباين المرتفع، فاصل تحديث لوحة التحكم، والنموذج النصي المحلي الافتراضي. يمكن تصدير التفضيلات واستعادتها دون رموز الدخول. يتوفر قفل اختياري لجلسة الوصول بعد 15 أو 30 أو 60 دقيقة من عدم النشاط؛ وهو حماية على مستوى جلسة المتصفح وليس بديلاً عن انتهاء صلاحية الرمز على الخادم.
- سولاراب هوب: استعراض مستودعات GitHub العامة وملفات الجذر وبيانات المستودع للقراءة فقط. لا يوجد تعديل أو دفع إلى المستودعات من هذه الواجهة.
- الجذر: فحص معلومات المتصفح والشاشة والاتصال والخصائص التي يسمح المتصفح بعرضها. لا تدّعي الصفحة امتلاك صلاحيات نظام التشغيل أو root.
- الخزنة: حفظ الملاحظات والأفكار والمهام والمراجع محلياً مع تصدير JSON.
- الوسائط المحلية: تكامل API مع ComfyUI لتشغيل سير عمل الصور، وwhisper.cpp لتفريغ الملفات الصوتية عند تشغيل المحركين على جهاز الخادم.
- الأمان: طلبات موافقة وسجل تدقيق عند اتصال الخادم، مع نقطة حالة مصادقة لا تكشف الأسرار. تعتمد النسخة الحالية على رمز API مشترك ولا توفر حسابات مستخدمين منفصلة أو إعادة تعيين كلمات مرور.
- التنفيذ الآمن: حفظ ملاحظة TXT/MD وتصدير فهرس Markdown لملفات المشروع (الأسماء والأحجام والتواريخ فقط)، مع استبعاد الملفات المخفية والروابط الرمزية ومفاتيح الوصول، وحد 200 ملف. جميع الإجراءات يدوية ومن قائمة سماح محددة.
- توليد الصور: يقبل ComfyUI مخطط الصور القياسي ذي العقد السبع فقط، مع حدود للأبعاد والخطوات والمرجعيات؛ لا يُسمح بعقد مخصصة أو تنفيذ عام.
- الرجوع: التنقل داخل سجل التطبيق مع دعم زر الرجوع في المتصفح والهاتف.

## البنية

- **Frontend:** React 18 + Vite، واجهة عربية RTL ومتجاوبة للهواتف والحواسيب.
- **Backend:** Python + FastAPI.
- **Storage:** SQLite محلياً كبداية، مع قابلية إضافة PostgreSQL عند الانتقال إلى خادم متعدد المستخدمين.
- **PWA:** manifest وService Worker للتثبيت والتخزين المؤقت.
- **Safety:** سجل تدقيق، طابور موافقات، وعدم تنفيذ أي إجراء لمجرد تسجيل الموافقة.

## التشغيل

### المتطلبات
- Node.js 20 أو أحدث.
- Python 3.10 أو أحدث.

### الخلفية
```bash
cd backend
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

### الواجهة
من جذر المستودع:
```bash
npm install
npm run dev
```
افتح عنوان Vite الظاهر في الطرفية. الواجهة تتصل افتراضياً بـ `http://127.0.0.1:8000`. لتغيير ذلك أنشئ ملف `.env.local` في الجذر وضع `VITE_API_BASE_URL=http://127.0.0.1:8000`.

## حالة المحركات المحلية

- `GET /api/engines/status`: يفحص llama.cpp وComfyUI وwhisper.cpp بالتوازي عبر عناوين loopback المهيأة، بمهلة خمس ثوانٍ لكل محرك.
- يعرض مركز العمليات حالة كل محرك منفصلة. فشل محرك واحد لا يمنع عرض حالة بقية المحركات.
- الفحص تشخيصي فقط ولا يرسل مهام توليد أو نصوص مستخدم إلى المحركات.

## استيراد المشاريع

- `POST /api/projects/import`: استعادة مشروع من أرشيف ZIP سبق تصديره، وإنشاء مساحة مشروع جديدة نشطة دون الكتابة فوق مشروع موجود.
- يتحقق الخادم من بيانات المشروع وأسماء الملفات، ويرفض مسارات ZIP المتداخلة والروابط الرمزية والملفات الخاصة والمشفرة، والملفات التنفيذية المحظورة.
- حد الملف المضغوط 50 MB، وحد المحتوى بعد فك الضغط 50 MB، وبحد أقصى 200 ملف. لا يستخدم الخادم `extractall`؛ تُكتب الملفات واحداً تلو الآخر داخل مساحة جديدة مع تنظيف المشروع الجزئي عند الفشل.
- تتطلب العملية رمز وصول صالحاً في وضع الإنتاج، وتسجل في سجل التدقيق.

## تصدير المشاريع

- `GET /api/projects/{id}/export`: تنزيل أرشيف ZIP للمشروع مع ملف بيانات `project.json`.
- يشمل التصدير الملفات العادية الموجودة مباشرة داخل مساحة المشروع؛ تُستبعد الروابط الرمزية والملفات غير العادية.
- الحد الأقصى 200 ملف و50 MB للمحتوى المصدّر. يتطلب endpoint رمز وصول صالحاً في وضع الإنتاج، ويسجل عملية التصدير في سجل التدقيق.
- يمكن تصدير المشاريع النشطة والمؤرشفة من بطاقة المشروع في الواجهة.

## طابور المهام

تُحفظ مهام مساحة الوكلاء في قاعدة SQLite على الخادم، وتُعرض من قسم «الوكلاء والأتمتة»: وتدعم في 0.11.0 إجراء حفظ ملف نصي داخل مساحة مشروع نشطة بعد الموافقة والتنفيذ اليدوي الصريح.

- `GET /api/tasks`: عرض آخر 200 مهمة، مع دعم التصفية عبر `?status=queued` أو إحدى الحالات المعروفة.
- `POST /api/tasks`: إنشاء مهمة مباشرة بحقول `title` و`description` و`department`.
- `POST /api/agent-plans`: إنشاء مهمة بحالة `waiting_approval` وطلب موافقة مرتبط بها داخل معاملة SQLite واحدة؛ يعيد معرّفي المهمة والموافقة.
- `POST /api/approvals/{id}/decision`: القرار المعتمد ينقل المهمة المرتبطة إلى `queued`، والرفض ينقلها إلى `cancelled`. الطلبات القديمة غير المرتبطة تستمر بالعمل دون تغيير.
- `POST /api/tasks/{id}/cancel`: إلغاء مهمة لم يبدأ تنفيذها وإغلاق طلب الموافقة المرتبط إذا كان لا يزال معلقاً. تُرفض محاولة إلغاء مهمة حالتها `running` لأن هذا الإصدار لا يملك آلية إيقاف عامل تنفيذ.
- `GET /api/tasks/{id}/events`: عرض سجل تغيّر حالات المهمة، بما في ذلك الإنشاء وقرار الموافقة والإلغاء.
- `GET /api/executions/registry`: عرض الإجراءات المسموح بها فقط.
- `POST /api/tasks/{id}/execute`: تشغيل إجراء `write_project_note` بعد أن تصبح المهمة `queued`؛ وإذا كانت مرتبطة بطلب موافقة فيجب أن تكون الموافقة `approved`. يتطلب مشروعاً نشطاً واسم ملف TXT/MD ومحتوى نصياً، ويحفظ الملف داخل مساحة المشروع فقط. لا يدعم shell أو تنفيذ كود أو اتصالات خارجية.
- الحالات المخزنة: `queued` و`planning` و`waiting_approval` و`running` و`completed` و`failed` و`cancelled`.

قرار الموافقة وحده لا يشغّل أي إجراء؛ ينقل المهمة المرتبطة إلى `queued` فقط. إنشاء الخطة والقرار والإلغاء يعيد `execution: not_started`. لا يوجد عامل تنفيذ خلفي أو جدولة تلقائية؛ الإجراء الوحيد المتاح حالياً هو `write_project_note` ويبدأه المستخدم يدوياً من واجهة الوكلاء بعد الموافقة.

## الأمان والخصوصية

- لا توجد بيانات دخول تجريبية مضمنة في الواجهة.
- الخادم محلي افتراضياً ويقبل CORS من عناوين التطوير المحلية فقط.
- في وضع الإنتاج يجب ضبط `SOULARAB_API_TOKEN` بقيمة قوية وسرية، وتقييد CORS إلى النطاقات الموثوقة، ووضع الخادم خلف HTTPS.
- لا تُسجل أسرار أو رموز وصول في المستودع.
- الموافقة على طلب تسجل القرار فقط؛ **لا تنفذ** أمراً أو اتصالاً أو تعديلاً. يلزم مسار تنفيذ منفصل ومراجعة أخرى.
- لا يوجد اتصال تلقائي بخدمة سحابية. تكامل llama.cpp يتصل بعنوان loopback فقط (localhost/127.0.0.1) على الجهاز نفسه، ولا يقبل عنواناً عاماً أو عنوان شبكة LAN.
- يتطلب تشغيل `llama-server` مع ملف نموذج GGUF محلي. عيّن `LLAMA_CPP_BASE_URL` فقط إلى عنوان loopback وبروتوكول HTTP.
- واجهة الهاتف لا تشغّل النموذج بنفسها؛ تستعمل الخادم المحلي كوسيط.

### تشغيل محرك روح المحلي
1. جهّز `llama.cpp` وابنِ `llama-server` على الجهاز المستهدف.
2. ضع نموذج GGUF محلياً، مثل `qwen2.5-3b-instruct-q4_k_m.gguf`، بعد مراجعة ترخيص النموذج ومتطلبات الذاكرة.
3. اضبط `LLAMA_MODEL_PATH` عند الحاجة ثم شغّل `bash scripts/start-rooh-engine-termux.sh` داخل Termux.
4. شغّل FastAPI كما سبق، ثم افتح قسم «روح». يستخدم الخادم واجهة llama.cpp المتوافقة مع OpenAI على `http://127.0.0.1:8081`.
5. عند فتح الواجهة من هاتف عبر الشبكة المحلية، أضف عنوان الواجهة إلى `SOULARAB_CORS_ORIGINS` في بيئة الخادم، مع إبقاء الوصول إلى API محمياً برمز قوي.

### محركات الوسائط المحلية

يمكن ربط محركات الوسائط دون استخدام خدمات سحابية:

- **ComfyUI:** اضبط `COMFYUI_BASE_URL` (الافتراضي `http://127.0.0.1:8188`). يعرض قسم الصور نماذج Checkpoint المثبتة تلقائياً، ويتيح إدخال وصف موجب وسلبي والأبعاد وخطوات التوليد لإنشاء سير عمل txt2img قياسي. يمكن أيضاً إرسال سير عمل API مخصص. تُعاد حالة المهمة ومعرّفها، ثم يمكن استعراض سجل النتائج وعرض صور المخرجات عبر وسيط آمن محدود بملفات الصور الناتجة. ضع النماذج في `models/checkpoints` داخل ComfyUI.
- **whisper.cpp:** اضبط `WHISPER_CPP_BASE_URL` (الافتراضي `http://127.0.0.1:8080`). شغّل خادم whisper.cpp مع واجهة `/health` و`/inference`، ثم ارفع ملفاً صوتياً مدعوماً من قسم الصور والصوت. الحد الأقصى 25 MB. يدعم WAV مباشرة؛ أما MP3 وM4A وOGG وWEBM وFLAC فتتطلب تشغيل whisper-server بخيار `--convert` وتثبيت FFmpeg.
- العناوين مقيدة بـ localhost أو loopback. في Docker فقط، يمكن تفعيل `SOULARAB_ALLOW_DOCKER_MEDIA=true` للسماح بأسماء خدمات `comfyui` و`whisper` داخل شبكة Docker الخاصة، مع ضبط العنوانين إلى أسماء الخدمات الصحيحة. لا تفتح منافذ هذه المحركات للإنترنت.
- وجود واجهة التكامل لا يعني أن المحرك مثبت؛ ستظهر الحالة غير متصلة حتى ينجح فحص الخدمة الفعلية.

### إدارة المشاريع
- من قسم «الملفات والمشاريع» أنشئ مساحة مشروع بعنوان ووصف.
- يحتفظ الخادم ببيانات المشاريع في SQLite وينشئ مجلداً منفصلاً داخل `backend/data/workspaces/<project-id>`.
- يمكن أرشفة المشروع دون حذف مجلده أو ملفاته.
- يمكن عرض ملفات المشروع ورفعها وتنزيلها وحذفها من الواجهة؛ الحذف يتطلب تأكيداً صريحاً، ويُمنع حذف ملفات المشاريع المؤرشفة. الحد الأقصى للرفع 10 MB للملف، وتُرفض المسارات والملفات التنفيذية الشائعة. لا توجد صلاحية لتصفح ملفات الجهاز خارج مجلد المشروع.

### النشر الذاتي باستخدام Docker
1. ثبّت Docker Engine وDocker Compose على جهاز الخادم.
2. انسخ ملف الإعدادات النموذجي: `cp .env.docker.example .env`.
3. غيّر `SOULARAB_API_TOKEN` إلى قيمة عشوائية قوية وسرية قبل التشغيل.
4. شغّل المنصة: `docker compose up -d --build`.
5. افتح `http://SERVER-IP:8080` من الهاتف أو الحاسوب على الشبكة المسموح بها.
6. محرك llama.cpp مستقل عن حاوية الواجهة والخلفية؛ شغّله على المضيف نفسه أو في بيئة محلية موثوقة، ولا تفتح منفذه للإنترنت.
7. البيانات تحفظ في Docker volumes ولا تُحفظ داخل صورة الحاوية.

**تنبيه أمني:** المنفذ 8080 يقدم HTTP. عند إتاحته عبر الإنترنت، ضعه خلف reverse proxy يدعم HTTPS، واستخدم نطاقاً موثوقاً، ولا تكشف منفذ FastAPI الداخلي 8000 أو خدمة llama.cpp للإنترنت. لا توجد عملية نشر تلقائي إلى الإنترنت.

## الوحدات المخطط لها

1. روح والنموذج المحلي: llama.cpp مع ملف GGUF بعد مراجعة الترخيص ومتطلبات الجهاز.
2. التصميم والوسائط: ComfyUI كخيار تكامل محلي، مع التحقق من متطلبات GPU.
3. الصوت: whisper.cpp.
4. أتمتة المتصفح: Playwright ضمن بيئة معزولة وموافقات لكل عملية مؤثرة.
5. المواقع والنشر والنطاقات: موصلات قابلة للتبديل، لا مفاتيح SaaS إجبارية.
6. إدارة المشاريع والملفات والنسخ الاحتياطية.
